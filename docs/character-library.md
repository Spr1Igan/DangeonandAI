# Библиотека рас и классов

## Как пользоваться

1. Открой «Расы» или «Классы» на странице персонажей.
2. Создай черновик, заполни описание и правила.
3. При необходимости сохрани дополнительные механики и сведения в JSON.
4. Нажми «Утвердить версию». После этого её содержание нельзя редактировать.
5. В мастерской персонажа раскрой «Выбрать расу и классы».
6. Выбери утверждённую расу и добавь классы с отдельным уровнем каждого.

Новая версия копирует выбранную утверждённую версию в черновик с очередным
номером. Одновременно у записи библиотеки допускается один черновик.
Персонажи продолжают использовать ранее выбранные версии.
Переход на новую версию выполняется явно в мастерской.

Архив запрещает изменения и новый выбор записи, но сохраняет ссылки
существующих персонажей. После восстановления запись снова доступна.
Расу и классы можно менять только у персонажа со статусом draft.

## Хранение

- races / race_versions: раса и её версии.
- game_classes / class_versions: класс и его версии. Модель GameClass
  названа так, потому что class — ключевое слово PHP.
- characters.race_version_id: выбранная версия расы.
- character_classes: выбранные классы, class_version_id и level.
  Ограничение уникальности по character_id + game_class_id не позволяет
  добавить один и тот же класс дважды. При выборе другой версии этого
  класса обновляется существующая связь.

Название принадлежит записи библиотеки и общее для всех её версий.
Описание, правила, mechanics и metadata принадлежат версии.
Номер версии, владелец и статус не берутся из входных данных пользователя.

## Сервисы для форм и будущего агента

RaceService и GameClassService предоставляют:

- createDraft(user, input)
- updateDraft(user, entryId, versionId, input)
- finalize(user, entryId, versionId)
- createVersion(user, entryId, sourceVersionId)
- archive(user, entryId)
- restore(user, entryId)

CharacterBuildService предоставляет:

- setRace(user, characterId, versionId), null снимает выбор расы.
- setClass(user, characterId, versionId, level).
- removeClass(user, characterId, selectionId), где selectionId — ID
  строки character_classes, а не класса или версии.

Пользователь берётся из авторизованной сессии. При подключении агента
эту же проверенную личность должен передавать сервер. Сервисы проверяют
принадлежность записей, статусы и используют транзакции с блокировками.
Не следует заменять их массовыми SQL/Eloquent update/delete:
массовые операции обходят защитные события моделей.

В updateDraft отсутствующие поля сохраняются, null очищает поле.
Переданный mechanics или metadata заменяет соответствующий JSON целиком.
HTML-формы передают mechanics_json и metadata_json; LibraryEntryRequest
преобразует их в массивы. Сервисы принимают готовые массивы.

## Что ещё не реализовано

ИИ пока не подключён. Для него потребуются инструменты вызова сервисов
и отдельный процесс подтверждения пользователем перед утверждением правил.

JSON хранит произвольные данные, но не исполняет правила. Назначение расы
или класса не изменяет автоматически HP, характеристики, способности
или ресурсы. Также пока не проверяются условия мультикласса и ограничения
уровней конкретной системы. Диапазон уровня 1–65535 — ограничение хранения;
ограничения конкретных правил предстоит добавить отдельно.
